# 交互契约（Interaction Spec）

> 方向：**划选即指令（selection-native agent）为主，画布为底**。
> 界面不是"笔记应用 + 侧栏 + 聊天框"，而是一个**可操作的知识空间**：
> 你圈/划/点哪里，就对哪里下指令，结果**原地**变成可直接用的知识对象（文件/节点），不是聊天记录。
>
> 本文件是与实现的契约：新增交互必须先在此登记原语与状态，不允许功能先行、交互随意。

## 1. 原则

1. **就地（in-place）**：动作浮在选区旁，结果落在原处；不强迫跳转对话框或新页面。
2. **选区即上下文**：任何选区（节点、文字、一块画布）都携带足够的"对象 + 容身之处"，agent 不必反问"你指谁"。
3. **产出是知识对象**：agent 产物一律落为 Markdown/节点/连线，可被任何编辑器打开——不是只有本应用能读的聊天流。
4. **先预览后落地**：改写类默认给 diff/预览，确认才写；破坏性操作可撤销。
5. **键盘优先**：全流程可无鼠标完成（存在对应快捷键）。

## 2. 五个原语

| 原语 | 手势 | 语义 | 现有实现 |
|---|---|---|---|
| **放 place** | 拖拽节点/文件 | 空间排布即组织 | 画布拖拽、`/doc/move` |
| **连 link** | 从一个节点拖到另一个 | 建立关系 | 画布连线（edges）、wikilink |
| **圈 select** | 空白拖拽框选 / 双击 | 选中对象集合 | `lasso`、`multiSel`、`batchbar` |
| **划 select-text** | 在正文/预览里划一段 | 选中"材料" | `#editor`、`#preview` |
| **令 command** | ⌘K / ⌘. / `/` | 对当前选区下指令 | `palette-ov`、`slash-menu`（新增 `⌘.`） |

## 3. 统一选区模型

一个全局 `Selection`（前端状态 + 契约），任何动作面板都由它派生：

```
Selection =
  | { kind: 'nodes',   ids: [nodeId], paths: [string] }        // 画布单选/框选
  | { kind: 'text',    path: string, range: [start,end], text } // 正文划选
  | { kind: 'region',  nodeIds: [nodeId] }                      // 画布一块（= nodes 批量）
  | { kind: 'none' }
```

规则：
- 选区变化 → **动作栏（Action Bar）** 重新计算可用动词；无选区则不显示。
- 画布节点选中与编辑器文字选中**互斥切换**（进入编辑区清空节点选择，反之亦然）。
- 多选（`圈`）走批量语义；单向操作对多选降级为"逐项执行 + 汇总"。

## 4. 动作栏（Action Bar）·签名交互

浮层 `#actionbar`，锚定选区（文字选区取末行右侧；节点取节点上方；批量取框右上）。键盘 `⌘.` 唤起并聚焦搜索框。

### 4.1 文本选区动词（编辑器/预览）

| 动词 | 语义 | 结果落点 |
|---|---|---|
| 改写 | 同一意思重述 | 就地替换（diff 预览） |
| 扩写 | 展开为更完整段落 | 就地追加/替换 |
| 精简 | 压缩 | 就地替换 |
| 总结 | 提炼要点 | 就地插入要点块 |
| 翻译 | 换语言 | 就地替换 |
| 提取为节点 | 变成独立文档/画布节点 | 新文档 + 自动连线到来源 |
| 提问 | 以该段为上下文对话 | 动作栏内联回答，可"插入" |

### 4.2 节点选区动词（画布）

| 动词 | 语义 | 结果落点 |
|---|---|---|
| 总结 | 概述该节点 | 新节点（连线到原节点） |
| 扩写 | 从提纲长成正文 | 写回该文档 |
| 连到… | 建立关系 | 新边（写 wikilink） |
| 合并 | 多个节点合成一篇 | 新文档 + 保留来源链接 |
| 打标签 | 批量加 tag | frontmatter |
| 生成结构 | 把一批节点整理成层级/综述页 | 新文档 + 新目录 |

### 4.3 画布动词
对空白/整库：`整理布局`、`生成今日综述`、`找出未连接的孤儿节点`、`按主题聚类`。

## 5. 与视图/模式的关系

- **视图**（画布/时间线/看板）= 同一 `Selection` 的不同排布，动作栏不随视图变化。
- **模式**（Studio/整理/学习/Memo/展示/RAG/线上/Agent）= 动作栏动词集的"预设包"：
  - 整理：动词偏向 `打标签/合并/生成结构`；
  - 学习：偏向 `总结/提问/提取为节点`；
  - Agent：动作栏常驻 + 对话作为兜底；
  - 其余模式动作栏默认隐藏，仅 `⌘.` 显式唤起。
- 动作栏与 `⌘K` 命令面板**同源**（同一 `COMMANDS` 注册表），只是一个面向"选区"、一个面向"全局"。

## 6. 结果与撤销

- 落点三选一：**就地编辑** / **新节点** / **新文档**；一律经 op-log（CRDT）写入，可撤销。
- 改写类：先出 diff 预览（`接受 / 重试 / 取消`），再写。
- 长任务：动作栏显示进度（复用状态栏 `#sb-sync` 式进度），不阻塞其他操作。
- 撤销：`⌘Z` 回退最近一次 agent 写入（依赖 op-log，粒度到一次"动作"）。

## 7. 键盘

| 组合 | 动作 |
|---|---|
| `⌘K` | 命令 / 检索（已有） |
| `⌘.` | 对当前选区唤起动作栏（新增） |
| `/` | 编辑器内插入菜单（已有） |
| `@` | 引用节点（新增：插入 wikilink/mention） |
| `Esc` | 关闭最上层浮层 |
| `Delete` | 选中节点 → 移入回收站（可恢复；⌘K「回收站」查看/恢复/彻底删除）（新增） |
| `1/2/3` | 切视图（已有） |
| `F/T/N/M` | 适配/整理/新建/整理模式（已有） |
| `⌘Z` / `⇧⌘Z` | 撤销/重做 agent 写入（新增） |

## 8. 后端契约

动作栏动词 → 内核能力（HTTP / MCP 同一套）：

- 文本动词 → `POST /chat`（或 `POST /agent/apply`）：入参 `{op, path?, range?, text, target}`，出参 `{markdown|patch, placement}`。
- 节点动词 → `/doc`(读写)、`/doc/move`、`/board`、新增 `POST /agent/apply`。
- 离线/命令模式：无模型时降级为**规则动词**（提取要点=标题/列表摘要、连到=相似度>T 的建议、打标签=关键词），保证动作栏在无 AI 时仍可用。
- MCP：以上动词各暴露为 tool，供外部 agent 复用同一语义。

## 9. 非目标

- 不做"只能在本应用内读"的聊天式产出。
- 不引入隐藏状态：动作栏只做当前选区的显式操作。
- 不用 AI 取代鼠标可达的所有操作——键盘/鼠标永远有等价路径。

## 10. 分期与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0** | 编辑器文本划选动作栏：改写/扩写/精简/总结/提取为节点（+ 无模型规则降级） | 划一段 → ⌘. → 选动词 → 就地 diff → 接受后落盘；`⌘Z` 可撤 |
| **P1** | 画布节点动作栏 + 框选批量（总结/连线/合并/打标签/生成结构） | 选中节点 → 动作出新节点并自动连线；批量操作可撤销 |
| **P2** | 对话生长画布：一句指令长出节点/连线/分组；`@` 引用 | 对话产物直接是画布上可拖可编辑的对象 |

## 11. 开放问题

- 模型不可用/离线时的动词质量下限（规则降级要写到什么程度）？
- 写入落点的默认选择（就地 vs 新节点）是否要按动词固定、还是记忆用户偏好？
- 长文档整篇改写 vs 选区改写的边界与性能（分块流式）。
- `privacy=local` 下动词一律本机模型，哪些动词允许降级为规则。
