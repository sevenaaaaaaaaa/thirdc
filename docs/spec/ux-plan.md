# ThirdC UX Plan — 让每一件事都看得见

规则：**功能不可见 = 没做**。任何能力必须在界面上有入口、有状态、有反馈。

## 三、魔法感从哪来（机制，不是特效堆砌）

1. **流式**：agent 的每一步工具调用即时上屏（SSE），不等待整轮结束。
2. **空间反馈**：agent 产出的东西**落到画布上**并自动取景，而不是消失在聊天记录里。
3. **入场动效**：节点弹簧入场（错峰 35ms）、边渐进绘制、镜头弹簧过渡。
4. **思考光晕**：对话舱处理时呼吸光环 + 画布柔光扫过，结束即消散。
5. **打字机回复**：回复逐字浮现，可点「跳过」。
6. 原则：动效服务于因果可见性（谁触发了什么、东西从哪来），不做无意义炫技。

## 四、状态设计（不许有裸页面）

- 空库：画布中央一张卡片，三个起点（新建 / 粘贴网址 / 连接 MCP）
- 加载：骨架节点 + 呼吸；错误：可重试卡片（含错误码）
- 每条 agent 步骤三态：进行中（脉冲）/ 成功 / 失败（红色，可展开原因）
- 危险操作（删除文档）二次确认，且明确"文件真相将被移除"

## 六、UX-3 实现说明

### 三种视图（同一份数据，三种排布）
| 视图 | 排布依据 | 交互 |
|---|---|---|
| 画布 | 手动位置（`board.nodes`，sidecar） | 拖节点定位，`整理` 重排，`适配` 取景 |
| 时间线 | 文档 mtime 分组 + 类型泳道（文档/采集/附件/检索） | 只读排布，可平移缩放 |
| 看板 | 集合（`Notes/` 下第一层目录，`Sources/**` 归一为「采集」，根目录为「(根)」） | **拖卡片到另一栏即移动文件**（`POST /doc/move`），分栏为空时自动建目录 |

### 多画布
`.thirdc/boards/<name>.json`，默认 `main` 不可删；切换画布只换位置数据，内容仍是同一份文件真相。

### 已知边界
- 移动文档会改变路径；op-log 以路径为键，因此移动后文档获得新的 op 历史（内容不丢，历史不延续）。
  未来按内容 ID 建索引可修复。
- 看板分栏依赖目录结构：这是刻意的——**组织即文件系统**，不做隐藏元数据。
