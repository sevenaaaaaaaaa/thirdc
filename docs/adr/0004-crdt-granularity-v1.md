# ADR-0004 — V1 整文 CRDT，块级合并列 M4

日期：2026-09-18 · 状态：已被 M4 落地修订（实现方式见 ADR-0005）

## 背景

M2 已实现 Automerge 增量 op-log 与同步协议，两库可收敛。但当前 CRDT 单元是"整篇文档的块模型 JSON"（存为一个 Text 对象）。

## 决策

V1 接受整文替换语义：并发编辑**同一篇文档**时按 Automerge 确定性规则收敛，但可能只保留一方内容（last-writer-wins 的整文结果）。并发编辑**不同文档**完整合流。

块级合并（含稳定块 ID、顺序的分数索引、逐块 diff）列入 M4，不与 M2/M3 混做。

## 理由

- 块级合并的正确性依赖两个前置设计：**内容派生的稳定块 ID** 与 **分数索引顺序表**。两者都需要独立设计与测试，匆忙实现会引入难以复现的丢内容 bug。
- 协作的真实高频场景是"不同人改不同文档 / 不同章节"，当前实现已覆盖；同段并发编辑的正确处理值得单独一个里程碑。
- 先让同步协议、增量日志、冲突收敛这些地基经受验证，再上层细化合并粒度。

## 后果

- 文档需明确记录该边界（docs/spec/sync-protocol.md「已知边界」）。
- M4 设计要点：`blocks: Map<block_id, block>` + `order: List<block_id>`（分数索引），import 时用 LCS diff 只增删变化块，保证并发插入的块两侧都保留。
